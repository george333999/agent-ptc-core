Basis and methodology

  1. FairnessAll comparisons are executed alternately in ABBA order within the same time window, avoiding the time-of-day bias of running the Optimized version during the morning peak and the control version at dawn.
  2. Control groupThe Baseline Agent uses the full history + native function calling + single-loop ReAct, with all context pruning, distillation, prefetching, PTC and orchestration optimizations disabled; it is not a backup version.
  3. CostBoth groups are uniformly recomputed at the official DeepSeek off-peak price: cache hit 0.02 CNY, cache miss 1 CNY, output 4 CNY per million tokens. Actual billing is priced by peak/off-peak at each turn's send time; the reported cost is used for like-for-like comparison.
  4. AccuracyBased on whether the user task is actually resolved: Excel files must be genuinely generated and readable, Markdown/JSON must be written to disk and pass content validation; returned errors, missing files and invalid files all count as failures.
  5. LongThe Long group uses four valid runs: 2 opt + 2 base. Two runs with obvious server-side stalls were excluded (opt single-turn 192s, base P95 22.6s); all other failed turns are included, with no favorable filtering. In the base run at 03:41, all 11 Excel turns failed (converted to CSV after generation and the xlsx deleted), counted as genuinely unresolved.
  6. ConclusionThe Optimized version's advantage in tokens and cost expands rapidly as conversations grow longer; the wall-clock gap mainly stems from the number of model calls and time to first token, which is a model-side bottleneck, so further optimizing in-framework tooling has very low marginal benefit for wall-clock time.
