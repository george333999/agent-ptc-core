口径与方法

  1. 公平性所有对比都在同一时间窗口内按 ABBA 顺序交替执行，避免早高峰跑优化版、凌晨跑对照版造成的时段偏差。
  2. 对照组传统框架 Agent 使用全量历史 + 原生 function calling + 单循环 ReAct，关闭全部上下文裁剪、蒸馏、预取、PTC 与编排优化；不是备份版本。
  3. 金额两组统一按 DeepSeek 官方空闲价重算：缓存命中 0.02 元、未命中 1 元、输出 4 元每百万 token。实际账单按每轮发送时间峰谷计价，报告金额用于同口径比较。
  4. 准确率以用户任务是否真实解决为准：Excel 必须真实生成且可读取，Markdown/JSON 必须落盘且内容校验通过；返回错误、缺失文件、无效文件都计为失败。
  5. 长对话long 组使用 2 opt + 2 base 四个有效 run；剔除了两次明显的服务端卡顿 run（opt 单轮 192s、base P95 22.6s），其余失败轮次全部计入，未做有利筛选。base 在 03:41 的 run 中 11 个 Excel 轮全部失败（生成后转 CSV 并删除 xlsx），按真实未解决计入。
  6. 结论优化版在 Token/金额上随对话变长优势迅速扩大；墙钟差距主要来自模型调用次数与首字延迟，属于模型侧瓶颈，继续优化框架内部工具对墙钟的边际收益很低。
