下一步优化建议

  • 缓存前缀稳定性：继续冻结 system 与工具 schema 字节，避免任务中途插入动态上下文。这是当前收益最确定的一项。
  • 超长对话与回读延迟：100 轮后窗口硬上限成为主约束，蒸馏节省会被回读往返抵消。下一步优先做自适应蒸馏预算与批量回读，而不是继续加大压缩。缺点是多一次回读就多一轮模型往返，写操作密集或强串行任务会被拖慢。
  • 工具结果预算：对 JSON 与长文档继续下调初始预算，强制模型用 read_tool_result 分段回读。需要用 P90 耗时约束回读次数，不能只看 token 下降。
  • 适合场景：长期保持同一套上下文的多文件只读分析、跨文件重构、长报告与知识库问答收益最大；一次性短问答、单文件小改、强实时交互和无法审批的高风险写操作收益有限，甚至会被回读拖慢。
  • 准确性回归：把产物校验脚本接入 CI，任何优化改动都跑 8、20、40、100 轮回归，准确率下降时优先回退而不是继续调参。
